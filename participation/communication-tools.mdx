私たちのチームでは、「チャットの激流で重要事項が流れて消える」「複数アプリを行き来して疲弊する」という問題を避けるため、**「Nexloom」と「Discord/Slack」の役割を明確に切り分けたハイブリッド運用**を行います。情報の性質を「フロー（流れる会話）」と「ストック（残る資産）」の2種類に分類し、それぞれ最適なツールで管理することが基本方針です。

---

## 1. 役割分担マトリクス

フローとストックの情報がどのように流通するかを以下の図で確認してください。合意内容はチャットで議論した後、必ず Nexloom へ転記することがルールです。

```mermaid
flowchart LR
    subgraph Flow ["【フロー情報：即時連絡・会話】<br/>Discord または Slack"]
        F1["日常の雑談・相談・現場速報"]
        F2["もくもく作業通話（ボイスチャット）"]
        F3["外部通知ハブ（GitHub, Webhook）"]
    end

    subgraph Stock ["【ストック情報：公式資産・決定事項】<br/>Nexloom (Single Source of Truth)"]
        S1["組織ハンドブック・仕様書"]
        S2["正式な決定事項（Decision Log）"]
        S3["タスク・ToDo・進捗管理"]
        S4["AIミーティング議事録"]
    end

    Flow -- "合意内容を要約して転記" --> Stock
    Stock -. "Webhook通知で更新を自動共有" .-> Flow
```

| 区分 | 📘 Nexloom | 💬 Discord / Slack |
| :--- | :--- | :--- |
| **主な用途** | **ナレッジ・決定事項・タスク・AI議事録** | **日常チャット・即時連絡・雑談・作業通話** |
| **情報の性質** | **ストック（恒久的に残すべき公式情報）** | **フロー（流れて消えても困らない情報）** |
| **強み** | ページ、タスク、会議録、AIが1か所に繋がる | 即時プッシュ通知、スマホ最適化、ボイス通話 |
| **具体例** | 組織ハンドブック改訂、タスク進捗、議事録 | 「今向かってます！」「これどう思う？」「作業部屋入ります」 |
| **原則** | **「ここで合意・記録されたものが公式の真実」** | **「決定事項は必ずNexloomへ記録する」** |

## 2. アプリ横断ストレスを減らす3大ルール

ツールを使い分けるうえで、以下の3つのルールを全メンバーが守ることで、情報の散逸と見落としを防ぎます。

<CardGroup cols={3}>
  <Card title="① チャットの決定は1行でNexloomへ" icon="pen-to-square">
    SlackやDiscordで議論して決まったことは、Nexloomの該当ページやタスクに1行で記録し、リンクをチャットに貼ります。
  </Card>

  <Card title="② Webhook連携で更新を見落とさない" icon="bell">
    Nexloomの更新通知はDiscord/Slackの特定チャンネルに自動連携。普段のチャットを見ていれば見落としません。
  </Card>

  <Card title="③ タスクや議事録は直接Nexloomで" icon="list-check">
    誰が何をいつまでにやるかは、チャットではなく最初からNexloomのタスクボード・会議録機能で作成します。
  </Card>
</CardGroup>

<Note>
  迷ったときの判断基準は「1週間後に誰かが参照したい情報か？」です。そうであれば Nexloom へ記録、そうでなければチャットで完結して構いません。
</Note>
